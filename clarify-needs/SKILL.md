# 需求锚定与拷问（v3.0-pre）

动手之前，把「要做什么 / 为什么这么做 / 做到什么算完」锚定住。
锚定强度分五档：**off / low / high / max / ultra**。档位决定问多深，也决定怎么问——不再另设模式。

## 1. 五档

| 档 | 语义 | 锚定度 | 复述 | 提问预算 | 动手条件 |
|---|---|---|---|---|---|
| **off** | 关闭锚定 | — | 无 | 0 题 | 立刻做，开头标一行「假设：…」 |
| **low** | 抓住大致方向 | ~60% | 一句 | ≤1 轮、≤2 题 | 方向对上就动手，细节边做边定 |
| **high** | 厘清核心方向 | 80% | 一句 + 2 个确认点 | ≤2 轮、≤3 题/轮 | 主路径没有分叉 |
| **max** | 挖清完整具体需要 | **95%** | 复述 + 3 确认点 + 风险/回滚 | ≤3 轮、≤3 题/轮 | 能写出无猜测的执行步骤 |
| **ultra** | 极致拷问 | 99% | 复述 → 设计树 → 共识摘要 | 多轮，直到 frontier 空 | 用户确认共识摘要 |

**锚定度** = 我能在不猜的前提下写出执行步骤的比例。

- **low**：知道做什么、动哪里；参数、顺序允许边做边定
- **high**：核心路径与关键分叉已定，只剩实现细节
- **max**：每步输入/输出/失败处理 + 边界/回滚/验收都定死
- **ultra**：每条分支都问到，不存在任何「默默假设」

## 2. 定档

顺序：**用户点名 > 自动评分 > 默认 high**。

用户直接说「用 low / 走 max / 锚定 ultra / 别问了」→ 立刻采用，不算分。

自动评分（四问，30 秒）：

| 问题 | 分 |
|---|---|
| 要动 ≥2 个对象，或跨目录 / 跨应用 | +1 |
| 只给目标、没给做法 | +1 |
| 在纠结「要不要做 / 选哪条路」 | +2 |
| 不可逆（删除 / 覆盖 / 迁移 / 花钱 / 对外） | +2 |

`0 = off，1 = low，2 = high，3 = max，≥4 = ultra`，再加三条地板：

- **只要不可逆 → 至少 max**
- **不可逆 且 在纠结方向 → ultra**
- **会改动文件 / 配置 / 系统的任务 → 最低 low**（off 只留给纯查询、纯只读）

### 升降档

| 触发 | 动作 |
|---|---|
| 「别问了 / 直接做 / 你自己决定」 | → off，执行前标「假设：…」 |
| 「大概方向就行 / 简单确认下」 | → low |
| 「仔细点 / 这个重要 / 别搞错」 | 升一档 |
| 「拷问我 / grill 我 / 往死里问」 | → ultra |
| 中途发现不可逆、或影响面变大 | 至少 max，并说明为什么升 |
| 同一问题问了两轮仍不到该档线 | 兜底：默认方案 + 风险 + 回滚，请回「按这个来」 |

## 3. 各档怎么做

### off

不提问、不复述。开头一行「假设：X；按 Y 处理」，然后做完。
用户没反对就继续；出现与假设冲突的事实，停下来说明，不许偷偷换假设。

### low

一句话复述：「你要的是「<目标>」，动「<对象>」，对吗？」
只问**方向性**问题（做不做 / 往左还是往右），不问参数和细节。
方向对上立刻动手；中途需要定的事，选最省事、最可逆的做法，并在收尾列出来。

### high（默认）

复述 + 2 个确认点：**要什么**（成功长什么样）、**动哪些**（文件 / 目录 / 应用）。
≤2 轮，每轮 ≤3 题。主路径没有分叉就开工，其余按默认处理并写进开头那行。

### max

复述 + 3 确认点：**要什么 / 动哪些 / 不能动什么**，再补**风险与回滚**。
≤3 轮。动手前自检五维，任何一项空白就说明没到 95%：

| 维度 | 问自己 |
|---|---|
| 目标 | 最终要什么结果？成功长什么样？ |
| 对象 | 具体哪些文件 / 目录 / 应用 / 账号 / 工作区？ |
| 边界 | 哪些不能动？只读还是可改？哪些必须保留？ |
| 约束 | 时间、预算、凭据、正在运行的进程、不可逆风险 |
| 优先级 | 速度优先还是安全优先？出问题先保哪个？ |

**95% 判据**：能不猜地写出执行步骤，每步输入 / 输出 / 失败处理都确定，且边界、回滚、验收标准也已定死。

- 有一个判断是「我觉得应该是…」→ 不到 95%
- 有一处「出问题再看」或「做完再说」→ 不到 95%

### ultra

设计树 + frontier 整轮拷问（见第 5 节）。收敛后给共识摘要，**用户确认前不动手**。

## 4. 通用规则

- 用 `ask_user_question`；low ≤2 题/轮，high / max ≤3 题/轮，ultra 3–5 题/轮
- 每题 2–4 个选项，**第一项标（推荐）**，并写一句该选项的代价
- 选项必须具体到可执行（路径、动作、数据去向），不要「是 / 否」这种空问题
- **事实我查，决策归你**：文件在不在、配置值、版本号、进程状态自己查，带着结论问；要耗时调查就派子代理，只有下游问题等它
- 用户已经说清的细节，任何档位都不再确认
- 不必每次念档位；只有升到 max / ultra 时值得说一句「这事不可逆 / 方向有分叉，先确认几点」

### 必须停手确认的动作

删除 / 移动 / 覆盖、改系统配置与注册表、动正在运行的程序、花钱、对外发送、批量重命名、改工作区或账号绑定。

### 执行中出现新歧义

不要自己补设定。停下来说一句：「发现 X，影响 A/B 两条路，你要哪条？」——同样给选项，按当前档位决定问完是否直接继续。

## 5. ultra：设计树与 frontier

目标不是「让用户同意」，而是把所有隐含假设挖到台面上。

- **设计树**：每个决策会分叉出依赖它的后续决策
- **frontier（前沿）**：所有前置条件已定的决策，此刻就能问、不必猜后续答案
- 一轮把**整个 frontier** 问完，然后停下等回答；下一轮重算 frontier

每轮格式（照抄）：

```
❓ **Q1** - **<问题标题>**：<问题正文，可含多段、可给多选>

➡️ <我的推荐答案>

---

❓ **Q2** - **<问题标题>**：<问题正文>

➡️ <我的推荐答案>
```

两条硬规则：

1. 措辞要让「是」等于接受我的推荐（回一个「是」就能推进）
2. 依赖仍未定问题的问题，属于**下一轮**，不许混进本轮

一轮 3–5 题；超过说明树没拆对，先砍分支。
**结束条件**：frontier 为空 → 给共识摘要（决策清单 + 理由 + 被否选项及原因）→ 问「以上是否就是你的意思？」→ 用户确认后才动手。

### 要留档时（ultra+）

| 产出 | 触发 | 位置与格式 |
|---|---|---|
| **ADR** | 做了以后不好改的决定 | `docs/adr/NNNN-<标题>.md`：背景 / 选项 / 结论 / 后果 / 回滚 |
| **术语表** | 同一个词两种意思，或新造词 | `GLOSSARY.md`：词条 / 定义 / 别称 / 反例 |
| 设计树快照 | 结论多、分支深 | 附在 ADR 末尾，画成缩进列表 |

需要完整方法论时调 `domain-modeling`；文件已存在先读再改，不要覆盖别人的记录。

## 6. 正例

**low** —「把 tmp 里过期的下载清一下」
→ 一句复述：「删 tmp 下 30 天前的下载，对吗？」→ 对 → 直接做，删完报清单。

**high** —「帮我把 ~/projects 整理一下」
→ 复述 + 2 确认点：成功长什么样（一眼找到项目 / 只是腾空间）、哪些目录算 projects
→ 主路径定了就动手，子目录命名沿用现有习惯。

**max** —「把 home 搬过来」
→ 先查：多大、有没有 junction、谁在引用、怎么回滚
→ 再问 3 点：搬不搬、旧路径留不留链接、回滚到哪一步 → 步骤写清再动。

**ultra** —「这套 token 治理要不要上」
→ 第一轮 frontier 三问：
  1. 目标是把账单压到多少？（推荐：先定 30% 降幅，可验）
  2. 允许改配置文件吗？（推荐：允许，但先备份）
  3. 出问题回滚到什么状态？（推荐：回到上一版 patch）
→ 答完展开下一层：分几个阶段、先做哪项、验收指标 → 共识摘要 → 动手。

## 7. 反例

- 「整理一下」就直接移动目录 → 打断 junction / 快捷方式，返工两次
- 「搬过来」只问「要不要搬」，没问「旧路径留不留」 → 后续新建会话失败
- 明摆着能自己查（文件是否存在），却问用户「那个文件在吗」
- ultra 一次抛 10 个问题 → 用户疲劳，只回前两个，后面的全成了默认假设
- 把「事实」和「决策」混在一起问 → 用户被迫替你查资料
- 该用 low 的琐事硬走 max → 三轮问答换一分钟改动

## 8. 收尾

无论哪档，**确认后把最终理解用 1–3 行钉在任务开头**（目标 / 对象 / 成功标准），后续按它验收；中途需求变了，重走一次对应档位的锚定。
