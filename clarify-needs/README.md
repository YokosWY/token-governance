# clarify-needs · 需求锚定与拷问

> 动手之前先定档：轻活不打扰，重活问到没有假设。
> 五档：**off / low / high / max / ultra**。
> **独立项目**，不并入 Token-Governance（TG）——两者是上下游关系，不是同一件事。
> **预发布**：随 TG 仓库一起分发，接口和档位还没定型，升级可能不兼容。

- 版本：**v3.0-pre**（预发：档位体系刚换成五档，仍可能调整）
- 技能名：`clarify-needs`（常驻，模型目录可见）
- 结构：1 个技能 + 2 篇文档 + 变更史

---

## 1. 它解决什么问题

Agent 最贵的开销不是「想太多」，而是**想错了重做**：方向错了 → 全部推倒 → 上下文重放再来一遍。
这类成本通常比任何压缩优化的收益都大一个量级。

| 症状 | 代价 |
|---|---|
| 说法含糊（「整理一下」「优化下」） | 做错方向，全量返工 |
| 方案没想清就开工 | 做到一半发现路不通 |
| 关键假设没人说出来 | 交付时才发现不是用户要的 |
| 只问「要不要」，不问「旧路径留不留」 | 后续步骤全崩 |

本技能把「问清楚」变成**有档位、有提问预算、有停止条件**的流程，而不是靠临场发挥。

## 2. 五档（怎么定量）

| 档 | 语义 | 锚定度 | 复述 | 提问预算 | 动手条件 |
|---|---|---|---|---|---|
| **off** | 关闭锚定 | — | 无 | 0 题 | 立刻做，开头标一行「假设：…」 |
| **low** | 抓住大致方向 | ~60% | 一句 | ≤1 轮、≤2 题 | 方向对上就动手，细节边做边定 |
| **high** | 厘清核心方向 | 80% | 一句 + 2 确认点 | ≤2 轮 | 主路径没有分叉 |
| **max** | 挖清完整具体需要 | **95%** | 复述 + 3 确认点 + 风险/回滚 | ≤3 轮 | 能写出无猜测的步骤 |
| **ultra** | 极致拷问 | 99% | 复述 → 设计树 → 共识摘要 | 多轮到 frontier 空 | 用户确认摘要 |

**定档顺序：用户点名 > 自动评分 > 默认 high。**

自动评分四问：

| 问题 | 加分 |
|---|---|
| 要动 ≥2 个对象，或跨目录/跨应用 | +1 |
| 只给目标、没给做法 | +1 |
| 已在纠结「要不要做 / 选哪条路」 | +2 |
| 不可逆（删除 / 覆盖 / 迁移 / 花钱 / 对外） | +2 |

`0 = off，1 = low，2 = high，3 = max，≥4 = ultra`，另加三条地板：

- 只要不可逆 → 至少 max
- 不可逆 且 在纠结方向 → ultra
- 会改动文件/配置/系统的任务 → 最低 low（off 只给纯只读）

**升降档**：说「别问了」→ off；「大概就行」→ low；「仔细点」→ 升一档；「拷问我」→ ultra；
中途发现不可逆 → 至少 max；同一问题两轮不达标 → 兜底给「默认方案 + 风险 + 回滚」。

## 3. 快速开始

无需安装脚本，复制目录即可：

```bash
cp -r clarify-needs ~/.dsh/skills/clarify-needs
```

装好后模型目录会出现 `clarify-needs`。它是**常驻**技能（每个请求都在上下文里），
不需要手动触发；要直接切档就说「用 max」「走 ultra」「别问了」。

---

## 4. 典型场景

| 场景 | 会走哪档 |
|---|---|
| 「这个文件多大」 | off（或 low）：直接查，一句话答完 |
| 「把 tmp 里过期下载清一下」 | low：一句复述 + 直接做，删完报清单 |
| 「帮我把 ~/projects 整理一下」 | high：复述 + 成功标准 + 范围 |
| 「把 home 搬过来」 | max：先查 junction/引用/回滚，再问留不留旧链接 |
| 「这套 token 治理要不要上」 | ultra：设计树 frontier 逐轮，结束给共识摘要 |
| 同一议题第三次讨论 | ultra + ADR：把「为什么否掉 A」写进决策记录 |

---

## 5. ultra 长什么样

每轮把**整个 frontier**（前置已定的决策）问完，格式固定：

```
❓ **Q1** - **问题标题**：问题正文

➡️ 我的推荐答案
```

三条硬规则：

1. 措辞让「是」等于接受推荐答案（回一个「是」就能推进）。
2. 依赖未定问题的问题属于**下一轮**，不许混进来。
3. **事实我查、决策归你**：能自己查的不问用户；要调查就派子代理，且只有下游问题等它。

结束条件：**frontier 为空** → 共识摘要（决策 + 理由 + 被否选项）→ 用户确认后才动手。

## 7. 设计取舍（详见 docs/design.md）

| 决定 | 理由 |
|---|---|
| **5 档**，不是 4 档 | 用户要的是「精度阶梯」：off 不锚、low 抓方向、high 80%、max 95%、ultra 拷问到没有假设；原 4 档把「抓方向」和「90%」压在同一档，中间态没有位置 |
| **档位自带方法**，不再单设 M1–M3 | 档位决定问多深，方法随之确定；两套轴（档位 × 模式）要交叉查表，反而慢 |
| **默认 high** | 日常「整理/改配置/装东西」落在 high；off 只给纯只读，防止「别问了」被滥用 |
| **档位可被用户点名** | 定档是模型自评，会错；用户一句话切档比模型算分可靠 |
| **不并入 TG** | TG 只认可度量；本技能拿不出指标，硬合并会破坏 TG 的「1 常驻」结构 |

## 8. 成本

| 项 | 值 |
|---|---|
| SKILL.md | 9.2 KB / 4,341 字符 ≈ **1,100 tokens** |
| 周重放（1 万步量级） | ≈ 12 M tokens |
| 缓存命中时 | ≈ ¥0.25/周（可忽略） |
| 未命中时 | ≈ ¥13/周（最坏情况） |

**真正的成本不是 token，而是多问一轮带来的行为开销**——由档位控制（off/low 少问不问）。

## 9. 已知边界

做不到的

- 无法证明「问对了更省」：这是**不可度量**的收益，只能靠少返工间接体现。
- 定档由模型自评，可能判错；靠用户点名 + 「别问了 / 仔细点」兜底。
- ultra 可能很长（2–3 轮 × 3–5 题），用户疲劳时收敛质量会下降。
- 档名 `low / high / max` 与推理 effort 同名，容易混淆——文档里已标注「同名不同义」。

不做的

- 不接管方案评审、代码评审。
- 不做成多技能包（必须单技能常驻，否则目录成本上升）。
