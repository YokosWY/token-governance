# 决策记录（改行为前先看这里）

## 2026-10-30 · 胶囊「累计」改名「累计省」；展开卡片摆全账目（本会话 / 本会话链 / 今日 / 省多少 / 命中率）

- 用户口径：气泡里的「累计」语义不清（是花了还是省了），改叫「**累计省**」；点开的卡片要把钱和率一次摆全，金额与命中率都保留 **3 位小数**。
- 卡片新增行：`本会话合计`（原）、`含 N 个子代理`（原）、`本会话链`、`今日花费`、`本会话省`、`累计省`、`命中率`；删掉不掉的旧行（未命中/步、上下文、回本步数）保留。
- `本会话链` 口径：同一条**血统链**（链首 + 转接出来的子会话），每个成员并上自己的子代理子树；同一文件只算一次（防子代理与链成员重叠双计）。
  - 成员来自 `lineageParents()`（5 秒缓存）；金额来自 `treeIndex()` 的逐文件全历史 `cny`（后台增量缓存，**不额外解压**）。
  - 本会话用 `account()` 的实时值覆盖索引值（索引最长滞后 60 秒），否则会出现「链合计 < 本会话」。
  - 索引里 `sid` 是**完整 uuid**，链 id 是 8 位：两边都归一到 `sid8()` 才能对上（实测踩过，`n:0` 全是这个坑）。
  - 索引没建好 / 成员没进索引 → `stale:true`，前端只在 `cny===null` 时写「统计中…」，不拿 0 冒充。
- 前端：`fmtCny3()`（¥x.xxx，正数不许落成 ¥0.000，<¥0.001 写 `¥<0.001`）、`fmtRate()`（xx.xxx%）、`fmtChain()`。
- 测试：新增 `tests/chain.test.mjs`（链首、单会话、完整 uuid、实时覆盖、stale 五条）；`trimstat` 的 J5 与 P1/P2 锁住「累计省」文案与卡片五行。

### 追加（同日·第二版）：卡片再加「本会话链省」；单会话也算一条链

- 用户追加：要**本会话链省多少**；并且**只有一个会话时也算一条会话链**（不显示成「没有链」）。
- `chain.n = 1` 时照常出数；前端 `fmtChain()` 一律带「· N 会话」，单会话显示 `¥1.410 · 1 会话`。
- 链省额 = 链上各成员（含各自子代理）的 `savedSelf.cny` 之和，与「本会话省」同一口径（配置反事实 + 工具输出压缩，不含预测）。
  - 省额没有现成索引：`savedOfPath()` 按 `path` 记忆 `{mt, cny}`（`decompress + analyzeSession`），链上除本会话外基本是闲的 → 每文件只算一次；本会话直接用 `account()` 已算好的 `savedSelf`，不重复解压。
  - 实测（session `e244fcb5` ↔ 链首 `c3dd7e8f`）：花费 ¥2.389、省 ¥1.414（两成员 0.847 + 0.567），首算 148ms / 73ms，热 0–2ms，两向一致。
  - 拿不到省额 → `savedCny:null` + `savedN:0`，前端写「统计中…」，不写 ¥0.000。
- 顺序（同日·第三版，用户要求「同类型的花费和省放在一起」）：按**作用域成对**排——本会话合计 →（含 N 子代理）→ 本会话省 → 本会话链 → 本会话链省 → 今日花费 → 今日省 → 累计省 → 命中率 → 未命中/步 → 上下文 → 回本步数。
  - 即：看一眼同一作用域就能同时看到「花了多少 / 省了多少」，不再把花费类与省类各自堆起来。

### 追加（同日·第四版）：再加「今日省」

- 口径：`analyzeSession(raw, { since })` 新增**今日窗口**——只算 `since`（本地日 0 点）之后进上下文的 schema / 技能目录 / 工具输出压缩，同一遍解析顺带算，不额外解压；无 `time` 的老事件按今天算（与费用侧「今日」一致）。
  - 窗口内的反事实比例（tokens/字符、blended 价）用窗口自己的数算，不拿全历史比例硬套。
  - 压缩收益按事件时间过滤：昨天压的块今天不再计；`winAfter = 窗口步数 − 事件前的窗口步数`。
- 落地：`analyzeSession` 返回 `todaySaved`；`refreshDay` 逐文件存 `saved`（`DAY_V` 2→3，旧缓存作废重扫今天）；`todayFromCache(..., selfTodaySaved)` 与花费同一条「缓存 − 本会话 + 实时」的路；`payload.today.saved`；memo 命中分支用 `cached.selfTodaySaved`（否则第二次请求会漏掉本会话那份额）。
- 实测（`18ba8815`，同一会话）：`todaySaved 0.643 / savedSelf 0.671`，今日合计 `cny 5.532 / saved 5.034`，首次与 memo 二次一致。
- 测试：`today.test.mjs` 加 3 条（省额相减、缓存缺失直接加、无省额给 0）；`trimstat` P2/P3 锁住「今日省」行与成对顺序。

## 2026-10-30 · rc.4 的会话目录改名 `session-<uuid>`，索引命中反向不成立

- 现象：升级到 NEXT 0.2.1-rc.4 后胶囊在、但一直 `¥--`（`/cost` 返回 `ok:false`「未找到会话日志」）。
- 根因（本次优化引入的回归）：rc.4 的会话目录从 `<uuid>` 改成 `session-<uuid>`，事件里的 id 也带前缀；
  `lib/scan.js` 的 `sidOf()` 会把目录名的 `session-` 剥掉存成键，而 `find()` 当时拿原样的查询去
  `键.includes(查询)`——查询带前缀时就永远不成立（旧实现是「目录名 includes 查询」，所以老代码反而能中）。
- 修法：`find()` 先把查询的 `session-` 前缀也剥掉，再做精确/包含匹配；补 `tests/scan.test.mjs`
  「目录名带 session- 前缀，带/不带前缀都能命中」，141 条全过。
- 顺带记：rc.4 起宿主所有 webServer 路由都过一道 desktop 浏览器门（`decideDesktopBrowserAccess`），
  非 Electron 渲染端（curl、浏览器直连）一律 403 `Browser access is disabled`——**curl 探活不再适用**，
  要验路由得看渲染端或看状态文件副作用。

## 2026-10-29（优化轮）· 扫描索引、原子写、观察面收窄

- `/cost` 每 5 秒一次，而一次请求里 `findSession` 会跑两遍（`account` + `sessionSid`），
  `savedFiles` / `dayFiles` / `treeFiles` 各自再扫一遍 sessions：222 个会话 ≈ 20 ms/遍，
  Windows Defender 下更慢 → 每 5 秒一次 20–45 ms 的同步阻塞。
- 新增 `lib/scan.js`：**按 sid 的常驻路径表**（命中只 stat 一个文件，≈0.2 ms）+ **全量列表 2 秒 TTL**。
  `findSession` / `savedFiles` / `dayFiles` / `treeFiles` 全部改成消费它；`turn/start`、`turn/end` 调 `invalidate()`。
  TTL 内的代价是「刚建的会话目录最多晚 2 秒被看见」——可接受，因为命名会话走路径表不需要扫。
- `readTrim()` 加 mtime+size 缓存并**返回克隆**：它在每步拼 system prompt 时都会被调；`/trim` POST 是就地改对象，
  不克隆会把缓存本体改脏。`writeTrim()` 写完直接失效缓存。
- 状态文件 7 处写入改 `writeFileAtomic()`（同目录 `.tmp` + rename，失败退回直写并清 `.tmp`）：
  半截 JSON 会被读路径当成「没有」，自动切换/今日缓存会静默重置，且无报错。
- 侧栏链标的 `MutationObserver` 从 `document.body` 收到「侧栏行容器」：流式输出时 body 整棵子树每 token 都变，
  回调被反复触发；现在只在行列表变化时响，容器被 React 换掉时 `armChainObs()` 自动重挂。
- 不改的：`lib/index.js` 仍是单文件（2626 行）。拆模块的收益是行数，代价是血缘/交接卡那一坨互相咬得很紧，
  硬拆要么循环 import 要么搬大段 state；当前 `_test` 出口 + 130 条测试已经够兜。下次要拆从 `pricing` / `trim` 两块无状态区下手。

## 2026-10-29（后）· 开关改链级，母对话唯一

- 开关是**一条链一份**，链内所有会话一致；在任意一节拨 = 整条链变（含已存在的和之后切出来的）。
- 链没被手动关过时**默认开**（用户从「母开子关」改过来；理由：链内要一致，母对话本来就是开）。
- 子对话再转接出来的**还是子对话**，链首是唯一母对话；「在子对话里打开」不再算升级成母对话。
- 基线 `armedTurn` 仍然**逐会话**存，不随链同步，否则会把母对话的基线带到新会话、一开就切。
- 链记录落链首 key；其它会话只留 `armedTurn`/`initializedAt`，旧数据在首次读到时提升（migrate-on-read）。

## 2026-10-29（后·四）· 链标不再挂官方插槽

- 官方源码（`@deepseek-ai/dsh-client-ui-workspace` 的 sessionRow）：`showStatus ? <SessionStatusDots/> : renderSlot("sidebar.session.row.leading")`。
  leading 槽宽 16×20，「进行中」的转圈圆点整格占用它，挂在槽里的角标**连挂载机会都没有** —— 这才是「圆圈挡住标记」的真相。
- 现在：不再注册该插槽，改成直接往行（`[data-row-key^="session:"]`）里 append 一个绝对定位小点，`left:1px; top:50%`，落在行的 `padding-inline-start: calc(8px + indent)` 里，与槽内图标（8px 起）互不遮挡。
- 同步机制：MutationObserver（150ms 防抖）+ 4s 轮询 + 血统刷新回调；行被 React 重建后自动补。
- 纯 Node 测试里没有 document，`installChainMarks()` 直接 return，定时器 `unref()`，避免测试进程挂住。

## 2026-10-29（后·三）· 行定位改用滚动容器的直接子元素

- 症状：「进行中」那行（左侧有转圈圆点）角标被圆点压住或看不见。
- 根因：`rowBoxOf` 按「最外层高度 ≤ 56px」猜行，带圆点/两行的行会把行内标题容器当成行，角标就摆到圆点那格去了。
- 现在先找侧栏滚动容器（`overflow-y: auto|scroll` 且高度 > 60），行 = 它的直接子元素；找不到才回退旧启发式。
- 角标仍在行左上角（坐标 0,0，`zIndex: 999`），正常情况下在图标左侧的内边距里，不与转圈圆点重叠。

## 2026-10-29（后·再）· 角标落位改成 offsetParent 绝对算

- 上一版 `fitMark` 增量补差值失效：它在 abs 切换前量到的是行内位置，补完又被重渲染覆盖，校验不过 → 退行内 → 视觉上跑到行底部/中间。
- 现在 `placeMark()`：`left = 行rect.left − 包含块rect.left − clientLeft`，一次算出，幂等；每次渲染都跑一遍（含 120ms 复钉一次）。
- 彻底去掉「跑偏就退行内」的兜底，宁可差 1px 也不跳到行底部。
- 角标 `zIndex: 999`，坐标从 (0,0) 起（负偏移会被 `overflow:hidden` 裁掉）。

## 2026-10-29（后）· 侧栏角标落位与压层

- 角标 `zIndex: 40`，压过官方状态圆点（橙/绿点），否则每次重渲染都被它盖。
- 不去猜包含块：`fitMark()` 用「量 getBoundingClientRect → 补 left/top 差值」跑两遍收敛，包含块是行还是行内某个定位元素都能落到行的真实左上角。
- 落位校验放宽到 ±3px；仍跑偏才退回行内画。之前的 0 → 24px 硬门限会把「差一点」误判成失败，退成行内（看起来就是跑到中间）。

## 2026-10-29（后）· 交接卡每轮都生成

## 2026-10-29 · 自动切换的母/子判定（开关部分已被上一条取代）

- **母对话** = 前面没有相关对话（血统链上没有 parent）→ 自动切换默认**开**。
- **子对话** = 已有母对话产生（链上有 parent）→ ~~默认关，不连环切~~ → **2026-10-29 后改为跟链一致**。
- 判定来源：`_local/tg-lineage.json` 的显式 parent，或续跑会话首条消息里的交接卡路径（`parentIndex`）。
- 用户显式开关**优先于**默认判定：记录带 `user:true` 时按记录来。
- 不按「是不是本插件切出来的」判定——那只是子对话的一种来源。

## 2026-10-29 · 转接时机（用户定）

- 每轮结束**只检查该不该切**（沿用「建议切换」判定），不自动跳。
- 该切 + 开关开 → 标记「待转接」、刷新交接卡。
- 用户按 **Enter** 发送时拦截：新建会话，预填 `交接卡路径 + 这次输入`，旧会话不收这条。
- 转接后**只预填**，不自动发送（用户按一次回车）。
- 只拦 Enter；点发送按钮不转接。拦截失败/转接失败：内容留在原输入框，照常发旧会话 + 胶囊提醒。
- 不做模拟回车：DSH 客户端没有发送 API，模拟键盘不可靠。
