# tg-orchestrate · 子代理分档

## 自适应（按可用档位与成本敏感度）

- **探测**：子代理工具是否支持 `reasoning_effort`；有几档模型；预算是否敏感。
- **分支 A（多档 + 子代理）**：主 High，难活 Max 子代理，审验 Max。
- **分支 B（单档模型）**：不派活，改为"主会话分步 + 自检清单"。
- **分支 C（无子代理能力）**：用两遍法——先草稿、再换视角自查。
- **分支 D（成本极敏感）**：只对"错了要重做"的任务用 Max，其余 Low。
- **都不可用**：退到 P12 的下半句——审验仍要≥产出档位，哪怕人工。

详见 `docs/adaptation.md` 的 C 节。

## 分档矩阵

| 任务 | 档位 | 谁做 |
|---|---|---|
| 读写文件、跑命令、格式转换 | Off / Low | 主会话 |
| 常规编码、整理、检索 | High | 主会话 |
| 架构设计、根因分析、数学证明、写方案 | **Max** | 子代理（fresh） |
| 批量抽取 / 清洗 / 翻译 | Low | 子代理（可并行） |

> 子代理调用参数：`reasoning_effort`（high / low / max，按发行版支持的写）。

## 派活判据

预计 **>20 步** 或 需要 **>30 k 上下文** → 派子代理；碎活自己做（子代理要自带完整任务书，1–3 k tokens）。

## 任务书五要素（缺一不可）

1. 目标（一句话，可验收）
2. 输入路径（具体文件）
3. 验收标准（什么算完成）
4. 输出格式（表格 / JSON / 文件）
5. 禁止事项（不要改什么、不要猜什么）

## 质量铁律

- **审验必须 Max**，且**不能是产出者本身**（避免自我确认）
- **低档位不得审高档位**产出
- 一次只派**一个** Max 子代理；并行只用于 Low 档批量活
- 子代理产出必须回主会话复核后才能进结论

## 实测（参考）

- Max 审计代理：8 条发现、带行号证据，有效
- Max 审验代理：把 3 条"高"压成 1 假 + 2 半，并抓出审计自身一处错判 → **审验这层不能省**
