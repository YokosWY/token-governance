# tg-memory · 会话记忆

## 自适应（按存储与协作形态）

- **探测**：`memory_root` 可写吗；是否多人/多代理共享；是否允许落盘原始日志。
- **分支 A（个人机，可写）**：完整 6 文件结构。
- **分支 B（合规受限，不能留原文）**：`30-logs/` 只存摘要+路径+哈希。
- **分支 C（共享记忆根）**：目录前加 `<user>/`，避免互相覆盖。
- **分支 D（无文件系统权限）**：退化为"会话内摘要 + 用户手动保存"。
- **都不可用**：只保留 `00-card.md` 一个文件（会话卡），其余全砍。

详见 `docs/adaptation.md` 的 G 节。

## 对话夹

**一个任务一个夹**（2026-10-25 起卡绑任务，不再按会话各建一个夹）：

```
${memory_root}/<workspace>/<任务名>/
  00-card.md      主卡 ≤40 行，覆盖写，接手第一眼看的
  01-<sid8>.md    同任务其他会话各自的卡（一张会话一张，互不覆盖）
  99-cards.json   索引：哪个会话在哪张卡、多少轮/步/¥（机器维护，人不用管）
  10-outline.md   大纲
  20-decisions.md 决策（追加，带日期）
  30-logs/        原始输出（正文只留路径）
  40-context.md   压缩摘要 + 指针
  90-links.md     产出/相关会话/外部来源
  handoff-gui.md  → GUI 区
  handoff-back.md ← GUI 区
```

会话归属哪个任务由指针 `_local/tg-current-task.json` 决定；没绑定的会话才退化成
`<YYYYMMDD>-auto-<sid8>/00-card.md`（临时快照，不算交接）。

脚手架：`python scripts/new_session.py <workspace> <id> "标题"`（若未提供，手建 6 个空文件即可）。

## 什么时候写（里程碑 + 4 触发器）

1. 一个可验收单元完成（构建通过 / 文件产出 / 问题闭环）
2. 产生决策（选型、放弃方案、改约定）
3. 上下文到 120 k
4. 踩坑修复后

外加：换任务或收工前必须写一次。**不要每轮写**——每轮写约 +¥8/周，收益极低。

## 分级

- 正文只写结论与**路径**；大段输出进 `30-logs/`
- `00-card.md` 覆盖写，永远只有当前状态
- 会话结束仍值得留的结论 → 提纯进长期记忆库

## 开工恢复

读顺序：`00-card.md`（主卡）→ `99-cards.json` 找本会话那张 → 对应 `01-<sid8>.md` → 都没有则读长期记忆库入口。

## 切会话前：一键出卡

```bash
# 首次：把本会话归到任务夹（只写指针，不出卡）
python scripts/handoff.py --session <id> --set-task 20261025-tg-account
# 之后：不带 --slug，自动按指针落任务夹
python scripts/handoff.py --session <id> --if-absent
# 没有任务/临时快照：显式给 slug，落 auto 夹
python scripts/handoff.py --session <id> --slug tg-account
```

- 指针文件 `_local/tg-current-task.json`，查法：精确会话 id → id 前 8 位 → `*`（本机默认任务）。
- 任务夹里首张卡写 `00-card.md`；同任务再来一个会话写 `01-<sid8>.md`；同一会话重跑按索引写回原卡。
- `--no-task` 忽略指针强制落 auto 夹；`--task <名>` 临时指定任务夹。
- `--config` 缺省读脚本旁的 `../config.yaml`，所以手跑不用带路径（早前靠 cwd，在别处跑会静默落 `~/tg-memory`）。

- 落点：绑了任务 → `<memory_root>/<workspace>/<任务名>/` 下首张 `00-card.md`、其后 `01-<sid8>.md`；没绑任务 → `<YYYYMMDD>-<slug>/00-card.md`。卡片结构（2026-10-25 改版）：**一行数字 + 改过什么 + 关键片段 + 状态（目标/最近指令/最后一句/卡在哪）+ 下一步**，删掉了原来的数字表和硬约束段——那两块占了篇幅却不给接手者信息。
- **自动填的**：
  - 头一行：`会话 <id>` + 轮/步/¥/ctx + 生成时间（2026-10-25 起卡片不写「回本/净省」，那两个数只留在胶囊悬停里）。会话 id 是回原日志的唯一把手，别删。
  - 「改过什么」：从会话日志的 `tool/call` 里收 write/edit 的 file_path（`/` 与 `\` 归一化去重、按次数排序、`tmp/`+`_tmp_*` 不算重点、最多 5 条，其余折成「另有 N 个」）。
  - 「关键片段」：取最后一次**够长的代码**改动（≥3 行、代码类扩展名优先、临时路径一律跳过、全量倒序找，≤8 行/600 字，围栏长度自动比正文最长反引号多 1）；没有代码改动才退到「最后写入的文本」。题注的来源按**本会话是否改过代码**判，不按取到那段是什么扩展名判。
  - 「状态·目标」：**首条**真人用户输入（≤80 字，按句读切，切不动才带 `…`）。末条常是「继续」「可以」，顶上去等于没交接。宿主注入的 system-reminder / 时间快照 / 技能目录不算。
  - 「状态·最近指令」：**末条**真人输入（≤80 字），有两条以上才写。它说明上一轮是不是按语。
  - 「状态·最后一句」：最后一条**含句子**的助手文本（只取 `type=text` 块、跳过纯表格/框线、≤160 字）。它是「最后说了什么」，**不表进度**——进度要人填。
  - 三条自动字段取不到时写「（无）」；真人输入全被过滤（压缩会话）才退到会话标题，不留空行。
- **要人填的**：「卡在哪」「下一步」——要从对话里读意图，机器写不准；片段里的重点行号同理。
- **净省口径**：`100 步净省 = 每步省 × 100 − 一次性重建（首屏上下文 + 卡片 3k）× 输入价`；≤0 说明还没到切的时候。面板检测到该切（`n* ≤ 15`）时单独显示这一行。
- `--if-absent` 不覆盖手写卡；`--print-only` 只打印；已存在时默认备份为 `.bak-时间戳` 再覆盖。
- **账目胶囊会自动跑这条命令**：`n* ≤ 15`（换会话回本步数）时宿主跑一次 `--if-absent`，卡片出现在弹窗里。
- **一键复制路径**（2026-10-25 定）：胶囊面板「复制路径」→ 剪贴板里只有卡片绝对路径，粘贴进新会话让模型自己 read（卡片本来就住在对话夹，不再复制正文）。宿主 `/tg-account/api/card` 仍返回正文，留给需要全文的场合。
- 硬约束：卡片 ≤3k token。重建超过 40k token 时，切会话省下的钱会赔回去。

## 输出瘦身子菜单（词元掌控面板）

- 面板「输出瘦身」→「详细 ▸」展开 7 条可单独开关的纪律（工具输出/历史轮次/文件全文/表格 JSON/日志/代码改动/客套总结）。
- 存储：`_local/tg-trim.json`（`{version:2, master, rules}`，v1 的按会话布尔值自动迁移成全局默认）。
- 生效点：宿主用 `ctx.inject(["systemPrompt"])` 挂一段 `tg-account:trim`（order 900），**每次拼 prompt 现读文件** → 改开关下一步就生效，不用重启；关总开关时那段文本为空串。
- 为啥不用硬依赖：把 `systemPrompt` 写进 `inject` 数组会让缺服务的环境整插件不加载，所以走可选注入。
