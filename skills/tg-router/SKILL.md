# TG · 词元掌控

管事不干活的元层：**先量、再改、再验、留退路**。

## 自适应（先探测再路由）

- **探测**：`${DSH_HOME}/storages/cost-meter/ledger.json` 是否存在；`skills_dir` 是否有 SKILL.md；客户端工具清单里有没有 `subagent` / `ask_user_question`。
- **分支 A（DSH 系，全功能）**：按五域路由，全部子技能可用。
- **分支 B（只有 skill 机制，没有 preset）**：跳过 `tg-context` 的 preset 部分，工具隔离改用子代理。
- **分支 C（纯方法论环境）**：不执行，只把包内 `docs/principles.md` 当参考读给用户。
- **都不可用**：退到 P3——只记录过程指标，不做收益承诺。

详见包内 `docs/adaptation.md` 的 A/C 两节。
**文档位置**：与 `skills/` 同级的 `docs/`；若按单技能目录安装，文档在项目根。

## 先认安装形态（30 秒，决定后面能不能跑命令）

```bash
ls scripts/tg_common.py 2>/dev/null || echo NO-SCRIPTS
```

| 结果 | 形态 | 怎么做 |
|---|---|---|
| 有输出（文件在） | **A · 完整仓库** | 下文的 `python scripts/*.py` 全部可用 |
| `NO-SCRIPTS` | **B · 只有 skills/** | 命令全不可用，按下面三条降级 |

形态 B 的三条降级（技能市场/手动拷 `skills/` 时最常见）：

1. 只用**方法论**：本包多数技能的价值在口径（存活计息、四项杠杆、压缩经济学），正文不依赖脚本；
   `docs/` 若也一并拷了就先读它，没拷就让用户补。
2. 告诉用户要跑数就得补仓库：`git clone <仓库> && cp -r <仓库>/scripts .`，或整体重装；
   **一句话说清缺什么**，别只回「跑不了」。
3. **禁止编造**：形态 B 下最容易犯的错是「报了一个没跑出来的数」。没有脚本就不给具体金额/占比，
   只给方法与需要用户自己量的指标。

## 开始前

读 `config.yaml`（与技能同级或项目根）。没有就用默认：`dsh_home=~/.dsh`、`memory_root=~/tg-memory`。
下文 `${DSH_HOME}` / `${TG_MEMORY}` 均指配置里的值。
跑脚本时 `dsh_home` 的解析顺序是 `--dsh-home` > config > `$DSH_HOME` > `~/.dsh`（实现只有一处：`scripts/tg_common.py`；装了两套客户端时先确认读的是哪一份）。

## 五域路由

| 你遇到的是 | 去哪 |
|---|---|
| 花太多钱 / 要算账 | `tg-cost` |
| 会话变慢变贵 / 想瘦身 | `tg-context` |
| 任务跨天 / 要接着上次 | `tg-memory` |
| 记忆库越堆越乱 / 要定「永久层」 | `tg-memlib` |
| 难活 / 要质量兜底 | `tg-orchestrate` |
| 要点界面 / 要截图 | `tg-gui` |
| 某类工具又贵又少用 | `tg-isolate` |
| 改 patch / 改 preset / 升级后 | `tg-ops` |
| 反复做同一个动作、被循环守卫点名 | `tg-loop` |

调起方式：`read ${SKILLS_DIR}/tg-cost/SKILL.md`，或用户 `/tg-cost`。

需要 memory 或 ops 时，先读包内 `docs/principles.md` 里对应原理（P9/P10/P11），
或问用户要不要补装——**不要凭空编造不存在的技能/路径**。

## 技能路由

本机技能多时，动手前先查而不是凭记忆挑：

```bash
ls ${SKILLS_DIR}                             # 列目录（本机 226 个，数量随机器变）
grep -il "<关键词>" ${SKILLS_DIR}/*/SKILL.md  # 可选：按正文粗筛
```
按目录名或 frontmatter `description` 选中后，直接 `read ${SKILLS_DIR}/<名>/SKILL.md`。

命中待机技能：`skill-on <名字>` 激活，用完 `skill-off`。
**被设了 `disable-model-invocation: true` 的技能，`skill` 工具调不到，但文件在
`${SKILLS_DIR}/<名>/SKILL.md` → 直接 `read`，效果等价。**

## 冲突处理：先问，不要直接改

安装或执行前，只要命中以下任一情况，**停下来问用户**，不要自行覆盖：

| 冲突 | 检测 | 该问什么 |
|---|---|---|
| 同名技能已存在 | `${SKILLS_DIR}/tg-router` 等路径已存在 | 覆盖 / 改名 / 跳过？ |
| 已有路由工具 | 已有别的 router 技能 / 路由脚本 | 并存 / 让它接管 / 替换？ |
| 已有记忆根 | `memory_root` 非空且不是本包创建 | 合并 / 另起目录？ |
| 已有配置 | `config.yaml` 存在但内容不同 | 覆盖 / 保留原值 / 备份后改？ |
| 已有补丁条目 | 目标 id 在补丁里已存在 | 合并 / 冲突项交给你手改？ |
| 目标窗口有凭据文件 | GUI 操作前扫描到 `*credential*` / `*key*` | 是否继续 / 换目标？ |

原则：**只读探测可以自己做，写操作一律先问**。预检脚本（形态 A 才有）：

```bash
python scripts/preflight.py --config config.yaml
```

输出「哪些冲突、建议怎么处理」，不修改任何文件；有冲突时退出码非 0。

日常先跑一条体检（只读）再决定去哪个子技能（形态 A）：

```bash
python scripts/doctor.py --days 7
```

它把体积、缓存、成本、失败率汇成一页，给 2–4 条带预估的动作；`--apply` 只做补丁快照与首日基线两件可回滚的事。

## 五条铁律

1. **过程指标不是证据**：工具数变少、配置生效、压缩触发，都不等于省钱。唯一证据是 cacheRead 下降 / 单价下降。
2. **压缩是安全阀，不是杠杆**：一次压缩 ≈ 新前缀按输入价重算一次，之后每步只省缓存价；实测净收益接近零，只用来防爆窗口。
3. **会重写的文件靠目录 ACL**：应用启动会重写组合配置，单文件权限撑不过一次重启。
4. **密钥先轮换、再清历史**：只删文件不轮换 = 没处理。
5. **改配置前先备份，备份先脱敏**：补丁里常有明文 key，`.bak` 会复制一份。

## 注入链体检（2026-10-23 基线，改完复测）

宿主 DSH 把 `$DSH_HOME/AGENTS.md` 注入每步前缀，这是 TG 管不到的固定成本；能管的只有分层与顺序。

| 环节 | 体积 | 频次 |
|---|---|---|
| `$DSH_HOME/AGENTS.md`（常驻） | 14.7 → **5.4 KB** | 每步 |
| `$DSH_HOME/AGENTS-tasks.md`（按需） | 7.2 KB | 触发才读 |
| `memory\CORE.md` | 2.7 KB | 每次会话 |
| `memory\INDEX.md` | 3.6 KB | 按需 |

口径与复测：

- 两份 AGENTS（官方 home / NEXT）必须 md5 一致：`md5sum <两份路径>`。
- 体积：`wc -c <四份路径>`。
- 任务说明（雷达/周报/AnySearch/对话夹）留在 `AGENTS-tasks.md`，**不要塞回常驻**；常驻只放纪律 + 触发条件。

## 步数纪律（2026-10-22 实测）

账单大头是「步数 × 每步上下文」，不是答案长度：8 天 10,150 步，cacheRead 占 43.7%、
output 27.4%，而 output 里推理占 45–49%、工具参数 41–46%、可见正文 7–14%（本机样本，比例可参考，绝对值随机器变）。

1. 一条命令合并多件事；只有互不依赖的只读命令才值得分开。
2. 大文件先 grep 定位行号，再 `read offset/limit`，不整文件读。
3. 到里程碑就落卡开新会话，不养 700+ 步的会话。
4. 子代理只在需要并行时开；每个子代理都是一次 cache miss。
5. 最后才考虑降档：effort high→low 只动 output 里的推理（上限约 6% 账单），质量兜底也没了。
