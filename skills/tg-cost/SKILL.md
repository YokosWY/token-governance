# tg-cost · 成本审计

## 自适应（先探测再算账）

- **探测**：账本有无 `costCny`/`cost`；会话日志有无 `usage`；账本 `config.currency`。
- **分支 A（有实付）**：直接汇总，报告写"实付"。
- **分支 B（只有日志）**：从 `usage` 汇总 token，用 `config.prices` 折算，报告写**"估算（假设 flash 价）"**。
- **分支 C（只有 API 账单）**：只做总量与趋势，归因部分标"不可用"。
- **分支 D（多机/共享）**：`dsh_homes` 合并 + 按 ledger 真实路径去重（账本只有日粒度，做不到按会话去重）；共享账户只报占比。
- **都不可用**：退到 P3，只测单次上下文均值与工具数。

详见 `docs/adaptation.md` 的 A/D/E 三节。

## 数据源

| 文件 | 内容 |
|---|---|
| `${DSH_HOME}/storages/cost-meter/ledger.json` | 真实计费：按天 / provider:model / 会话 |
| `${DSH_HOME}/sessions/<cwd>/session-*/session.v4.jsonl.zstd` | 逐 step usage + 内容，用于归因 |

多套 DSH → 分别跑，再合并（同一份 ledger 按真实路径只算一次）。

快速体检：`python scripts/cost_summary.py --config config.yaml`

行为观测：`python scripts/retry_patterns.py --dsh-home <home> --days 7` —— 出「换参重试」与「字面重复」两个数，只统计不拦截。2026-10-22 实测 73 个会话：换参候选 388 处，其中串内有报错的「失败重试」75 处（23 个会话），字面重复只有 6 处——重复的主体是失败后换参数再试。

## 归因口径（最容易错）

**上下文成本 = 内容 × 它在上下文里存活的步数**，不是一次注入。

```
示例：技能目录注入 322 M tokens
= 312 条注入 × 平均 22.2 k 字符 × 其后剩余步数
若只算"注入一次"会得到 1.6 M —— 差 200 倍
```

工具清单同理：`每步 schema token × 总步数`。

## 收益怎么算（边际口径）

1. 每项只在**剩余基数**上计收益，**上限不可相加**（上限合计 > 总花费就是笑话）。
2. 错峰/折扣是价格系数，与所有项**相乘**，不能单独相加。
3. 高单价通道的节省随上下文同步缩水 → 写成 `通道 × 其余项`。
4. **一次事故会话不计入稳态收益**（例：某会话 68 次调用 ¥91，占该通道 76%）。

## 验收指标（只有这三个算数）

| 指标 | 目标 |
|---|---|
| cacheRead 占比 / 单次成本 | 下降 |
| 单次上下文均值 | 常见 238 k → 目标 <180 k |
| 单会话峰值 | 不再破 400 k |
