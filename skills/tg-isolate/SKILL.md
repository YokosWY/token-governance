# tg-isolate · 高费低频工具隔离（通用模板）

> 把「只在少数会话用、但每次会话都按 schema 计费」的工具，搬进独立 preset；用之前先问用户装不装。
> GUI 区只是这个模板的一个实例，不是特例。

## 什么时候用

- 某类工具 **schema 大**（>20 个工具 / >20KB），但多数会话根本用不到
- 典型候选：computer-use / 浏览器自动化 / 大型 MCP 服务 / 音视频转码 / Office·PDF 渲染 / 3D·CAD / 数据库客户端 / 图像生成
- **反例（不要隔离）**：高频轻量工具（bash、read、grep、fs）——切 preset 的代价大于省下的 schema
- 反例：每次会话都要用、只是偶尔慢的工具——隔离它只会让你天天切区

## 第一步：量（不量不动手）

| 指标 | 取法 | 阈值 |
|---|---|---|
| 工具数 / schema 体积 | 工具清单、`request/header` 事件、宿主日志 | >20 个 或 >20KB |
| 调用频次 | 会话日志 / 账本 / 用户口述 | 每周 < 2 次 |
| 每步成本占比 | schema tokens × 总步数 × 缓存价 | >5% 才值得动 |
| 切换代价 | 每次切区 = 一次前缀 miss + 人工切会话 | 频次高则不划算 |

**判定式**：`高费（schema 大，每步都算）× 低频（多数会话不用）= 隔离候选`。
两项只满足一项 → 停，不做（写了也白写）。

## 第二步：出方案（先给方案，不落盘）

用 `templates/preset-isolate.yml` 生成：新 preset 的 `id / order / plugins`，服务型插件必须包组 + isolate。
写清三件事：**移走哪些工具、留在常规区的有哪些、切回方式**。

## 第三步：问（必做，不许替用户决定）

`ask_user_question` 固定三选一，话术照抄：

```
问题：检测到 <工具类> 的 schema 约 <N>KB，最近 30 天只用了 <M> 次。
      把它移进独立 preset「<name>」吗？（常规会话少这 <N>KB，需要时切区）
选项：
 A. 安装（推荐）—— 我改补丁层 + 备份，失败可一键回滚
 B. 只看方案不装 —— 我把 YAML 贴出来，你自己决定
 C. 取消 —— 保持现状
```

**禁止**：不问就改补丁；不问就删工具；把「我觉得该装」写成「已装」。

## 第四步：落（改补丁，不改 bundle）

- 目标文件：`<dsh_home>/profiles/<profile>/cordis.patch.yml`（人工补丁层）
- **不要**改 `cordis.yml`（运行时自动合成，会被覆盖）
- **不要**改 `package.json` / bundle（那是插件注册表，动静大）
- 改前备份到 `_backups/`，命名带时间戳；回滚 = 拷回 + 重启

## 第五步：验（没有对比数字就不算完成）

1. 新会话 / 重启后，看 preset 是否出现、是否 `加载失败`
2. 前后对比：**工具数、schema KB、单次成本、cacheRead 占比**
3. 失败立刻回滚，并把失败原因写进技能（别让下一个人再踩）

## 第六步：记账

写进 `03-决策与经验教训.md`：改了什么、实测省多少、**哪一条是猜的**（没实测就写"未验证"）。

## 硬规则（都是踩过的）

1. **服务型插件必须包组 + `isolate:`**，否则报 `Preset services require isolate realms` 直接加载失败
   ```yaml
   - id: <stack>
     name: cordis:group
     group: true
     isolate:
       <serviceKey>: true        # 键名来自插件声明的服务名
     config:
       - id: <plugin>
         name: '<vendor>/<plugin>'
   ```
2. **preset 的 `plugins` 是对象数组，补丁层不能按 id 寻址** → 只能整段覆盖该 preset
3. 顶层 id 可以寻址；但被 base 里 `disabled: true` 的影子条目挡住时，顶层覆盖**无效**
4. 改补丁**当天缓存全失效**，下一轮按 input 价重算整个前缀 → 攒批改、别一天改八遍
5. 切 preset 只影响**新会话**；当前会话不会热切换
6. 两套 DSH 各改各的 patch，别把官方 home 路径写进 NEXT
7. GUI 类工具另有交接协议（见 `tg-gui`）；本技能只管"隔离"，不管"怎么点"

## 分类速查

| 工具类 | 高费 | 低频 | 结论 |
|---|---|---|---|
| computer-use / cua | 是（几十工具） | 是 | 隔离（已落地 = preset gui） |
| 浏览器自动化（playwright 类） | 是 | 视任务 | 隔离，或按项目常驻 |
| 大型 MCP（>30 工具） | 是 | 视任务 | 隔离或按需启用 |
| 音视频/3D/Office 渲染 | 中 | 是 | 隔离 |
| bash/read/grep/fs | 否 | 否 | **不隔离** |
| 子代理/工作流 | 中 | 视任务 | 不隔离（编排要用） |

## 模板

`templates/preset-isolate.yml` —— 复制后替换占位符；基础段按发行版抄 standard。

## 交付格式

| 工具类 | schema KB | 30 天调用 | 判定 | 改动文件 | 回滚 | 实测收益 |
|---|---|---|---|---|---|---|
