# 并行拆分判据（fanout-criteria）

> 用途：判定「该不该拆并行、怎么拆、用哪个通道」，避免拆完更慢更贵。
> 数据口径：per-step 墙钟，`step/start` 与 `step/end` 配对计时，近 10 天 80 个会话，见 §4。
> 本文数字只来自 §4；其余系数为按公式推算的估算值，已标注推算过程。

## 1. 一页判据：六步，全过才拆

按顺序走，任一步不过就停止拆分、按串行执行。

1. **画依赖图，有效可切块数 k ≥ 3 且无环。**
   动作：列出子任务，标出「谁的输出是谁的输入」；链式或成环则有效并行度 = 1。
   反例：写代码 → 跑测试 → 修 bug 是一条串行链，拆成三个子代理只会互相等待，还要多付任务书与回传。
2. **每块能写出一行可机械判定的验收断言。**
   动作：为每块写「输入 X → 产出 Y → 判定条件 Z」；写不出说明块没切干净。
   反例：「把整个仓库风格统一一下」无法切块验收；可切成「按目录 A/B/C 各产出改动清单 + 校验命令输出」。
3. **用 §2 公式算出净值 > 0。**
   动作：估 n、p、t 与绝对开销（任务书 + 聚合），代入公式；Gain ≤ 0 不拆。开销近似固定，t 越小越容易被吃掉。
   反例：单块只有几十秒的任务，任务书 1–3k tokens 输入 + 主会话复读回传，就能抵掉约 40% 的步时收益。
4. **结果只需摘要回传，不需要主会话读全文。**
   动作：任务书里钉死回传格式（结论 ≤ 指定字数 + 证据路径:行号 + 不确定项）。
   反例：让子代理回传数千行改动全文，主会话仍要整读一遍，等于把并行省下的时间还回去。
5. **并发路数在通道上限内，同构任务用白名单模型。**
   动作：p 取 CT 代理档的 `maxChildren`（效率 2 / 性能 3，`dsh-calibration` 的 `AGENT_PLAN`）；同构批量用 `subagent`（白名单 deepseek-flash）。需要异构或更强模型才用 `agent_delegate`，且先跑 1 路小样本验证。
   反例：为「多模型投票」开 5 路，墙钟只省约 40%，成本 ×5。
6. **汇总阶段是机械合并（拼接/去重/排序/校验），不是再一轮推理。**
   动作：先写好合并步骤或脚本，再发子代理；汇总本身要写综述/做判断，就按串行重算。
   反例：5 份调研要交叉比对写成一篇综述，聚合成本接近一次完整长任务，并行净亏。

## 2. 收益估算公式

```
串行：T_serial   = n × t
并行：T_parallel = ceil(n / p) × t_sub + t_book + t_merge
判据：Gain       = T_serial − T_parallel > 0 才拆
```

| 符号 | 含义 | 取值口径 |
|---|---|---|
| n | 可切块数 | §1 第 1 步的依赖图 |
| p | 并发路数 | CT 代理档 `maxChildren`：效率 2 / 性能 3（`AGENT_PLAN`） |
| t | 单块在主线串行执行的墙钟 | 按同类任务历史估 |
| t_sub | 单块在子代理里的墙钟 | 按 0.6 × t 折算（子代理每步快约 40%，§4） |
| t_book | 写任务书耗时 | 任务书 1–3k tokens 输入的装配代价 |
| t_merge | 回传复读 + 合并耗时 | 由回传格式决定，全文回传最贵 |

- `t_sub = 0.6t` 是**步时代理**，不是任务级实测：子代理上下文独立，任务级还受任务书装配与结果复读影响，实际收益通常小于 40%。
- 把 `t_book + t_merge` 记为 `β·t`，β 是纯开销相对单块步时的倍数。

**全并行（p = n）化简**：
```
Gain > 0  ⇔  n·t > 0.6t + β·t  ⇔  n > 0.6 + β
```
- β ≈ 0.8（中等任务书 + 摘要回传）→ 需 n ≥ 2，接近临界，收益薄；
- β ≈ 2（大文件回传、要逐条核对）→ 需 n ≥ 3；
- β ≈ 5（汇总要再推理）→ 需 n ≥ 6，实际很少成立。

**p 受限时**：`T_parallel = ceil(n/p) × 0.6t + βt`。n 远大于 p 会多付批次，例如 n = 10、p = 4 需 3 批，比全并行多 1.2t；相对串行 10t 仍可能赚，但 β 大时会被吃掉。

**必亏的四种情形**：
1. n = 1：任何拆法都只加开销。
2. 依赖链：有效 n = 1。
3. β ≥ n − 0.6：开销超过收益。
4. 赛马（p 路跑同一任务）：墙钟 ≈ 0.6t + βt，省不到 40%，成本 ×p。

## 3. 本机执行方式

### 3.1 subagent 参数形态

```
subagent(
  description = "一句话标签（3–5 词，显示用）",
  prompt      = "<自包含任务书，五要素见 3.2>",
  cwd         = "<绝对路径；省略则继承当前目录>",
  # provider 与 model 必须同时给；都不给 = 继承当前会话路线
)
```

- 本机 `subagent` 白名单只有 `deepseek-flash`（provider：`deepseek-official` / `deepseek-account`，见 `D:\AI\DSH-NEXT\profiles\desktop\cordis.patch.yml:43-51`）。同构批量**不要**显式指定模型，省略即继承，可避免白名单报错。
- 确需显式时：`provider="deepseek-official"` + `model="deepseek-flash"` 成对出现；`reasoning_effort` 可选，按适配器支持填（不支持就别填）。
- 子代理不共享上下文：它看不到本会话历史，任务书必须自带 1–3k tokens 的背景。

### 3.2 任务书五要素模板

```
1. 目标与验收：<一句话目标>；完成标准 = <可机械判定的断言>
2. 输入与位置：<绝对路径 / 命令>；禁止自行搜索其他目录
3. 边界：只读 <…>；只写 <…>；不执行 <统计脚本 / 改配置 / 联网>
4. 回传格式：结论 ≤ N 字 + 证据路径:行号 + 不确定项；禁止回传全文
5. 预算与止损：最多 N 步；到限交回半成品并说明卡点
```

### 3.3 agent_delegate 适用边界

| 维度 | 适用 | 不适用 |
|---|---|---|
| 模型 | 需要非 deepseek-flash 的异构/更强模型 | 同构批量（走 subagent 白名单） |
| 规模 | 单点难活 1–2 路 | 大规模 fanout（无额度护栏） |
| 失败处理 | 自动回退官方 deepseek 并提示，需人工看回退原因 | 要求模型身份严格固定的产出 |
| 成本 | 按次谨用 | 赛马 / 多模型投票 |

## 5. 反面清单

1. **赛马**：同一任务开 N 路取最快或投票。墙钟只省约 40%，成本 ×N，不改变单步耗时结构。
2. **伪并行**：任务书要求子代理「参考主会话上下文」，或块间通过同一中间文件互相等待——实际串行，还多付一次回传。
3. **为了并行而并行**：n = 1 也拆、几十秒的任务拆 5 份、一个 prompt 能干完的事拆成流水线。
4. **把汇总当免费**：回传全文、要求主会话逐条比对，聚合开销直接吃掉收益。
5. **并行改同一文件**：两个子代理写同一路径，覆盖/冲突返工成本高于串行。
6. **用并行掩盖没想清楚**：写不出验收断言就拆，只是把模糊放大 N 倍。

## 6. 已知限制（必须随判据一起读）

1. 子代理不共享上下文，任务书须自带 1–3k tokens；结果回传后主会话还要读一遍。
2. 本机 subagent 白名单只有 deepseek-flash（`deepseek-official` / `deepseek-account`）；真正异构模型需走 `agent_delegate`（绕过白名单，失败会回退）。
3. 串行依赖链（写代码 → 跑测试 → 修）不能并行；赛马/多模型投票不省时、成本 N 倍。
